# GitHub Actions CI implementation plan

Date: 2026-11-23

## Purpose

Run Algor's existing checks automatically on pull requests and pushes to main.
Use the same Node.js 22, pnpm version from package.json, and PostgreSQL 17
that the project already uses. Add no application dependencies.

## Implementation

- [x] Add .github/workflows/ci.yml with pull_request, push to main, and
      workflow_dispatch triggers. Keep one stable check named Checks.
- [x] Give the workflow read access to repository contents, disable checkout
      credential persistence, cancel superseded runs, and set a 15 minute timeout.
- [x] Install pnpm from package.json, cache its store, and install dependencies
      with pnpm install --frozen-lockfile.
- [x] Start a health-checked postgres:17-alpine service with the disposable
      algor_test database on port 5434, matching vitest.config.ts.
- [x] Run typecheck, format:check, build, db:migrate, and test. Use test-only
      database credentials and no repository secrets.
- [x] Document triggers, checks, database setup, and local reproduction in README.md.

## Verification

- Validate workflow syntax with actionlint.
- Run the frozen dependency install and all workflow commands locally.
- Run migrations and tests against a fresh disposable PostgreSQL database.
- Review the diff for accidental application or agent instruction changes.
- Keep the CI workflow and its documentation in one conventional commit on a
  dedicated branch. Open a pull request so GitHub can exercise the workflow.

## Decisions

Use one job because the current project has one runtime and a small test suite.
Keep Vitest's existing serial file execution because integration suites share a
database. Migrate before testing to exercise the production migration command,
even though the integration suites also apply migrations.
